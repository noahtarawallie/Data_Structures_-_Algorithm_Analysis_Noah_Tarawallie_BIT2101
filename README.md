# DCOMP320 – Stack-Based Expression Evaluator

Evaluates mathematical expressions from `input.txt` using stacks and writes the results to `output.txt`.

## Requirements
Python 3.8+ (standard library only).

## How to run
```
python stack_evaluator.py                      # uses input.txt -> output.txt
python stack_evaluator.py my_in.txt my_out.txt # custom file names
```

## Files
| File | Purpose |
|---|---|
| `stack_evaluator.py` | Source code (Stack class, parser/evaluator, file I/O) |
| `input.txt` | Sample input used for testing |
| `output.txt` | Output generated by the program |

## Input format
- One expression per line.
- Expressions are separated by a line containing only dashes (e.g. `-----`).
- Supported: `+ - * /`, parentheses, decimals, unary minus (`-3 + 5`), spaces anywhere.

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

## Output format
Same layout as the input, with each expression replaced by its result and the same separator kept.

```
13
-----
16
-----
-10
```

## How it works
Two stacks are used (Dijkstra's two-stack method): a **value stack** for operands and an **operator stack** for operators and parentheses. Before pushing an operator, any operator on top of the stack with equal or higher precedence (`* /` over `+ -`) is applied first. A `)` applies operators until the matching `(` is found.

## Assumptions and limitations
- Whole-number results print without `.0`; other results print up to 6 decimal places (`7 / 2` → `3.5`).
- Division is true division (`7 / 2 = 3.5`, not 3).
- Invalid expressions do not crash the program; the output line becomes `Error: <reason>` (division by zero, mismatched parentheses, invalid expression/character).
- Blank lines in the input are ignored.
- Exponents (`^`), functions and variables are not supported.
- **Note:** the assignment sheet's sample output shows `17` for `(8 / 4) + 7 * 2`, but the correct value is `2 + 14 = 16`, which is what the program outputs.
